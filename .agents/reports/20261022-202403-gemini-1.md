## 2. Human Operator Issues

### Item 1 & 2: Test Isolation and Real Agents Home Guard
- **Problem:** During test execution, a legacy fixture (`agentbus/testdata/state-legacy.json`) containing host `WakeCmd` triggered real agent wake invocations on the host. In addition, tests running without isolated environments logged to `~/agents/logs/agentbus.jsonl`.
- **Solution:**
  - Implemented `TestMain` isolation in `agentbus/testmain_test.go`, `testmain_linux_test.go`, and `testmain_other_test.go`.
  - Configured isolated temporary directories for `HOME`, `AGENTS_HOME`, `AGENTBUS_DIR`, and `XDG_*` environment variables before tests run.
  - Provided default no-op recorders for `wakeFn` and `agentCmdFn`, intercepting side effects while preserving explicit test hooks (`captureWakes`).
  - Added a test file descriptor audit on Linux (`/proc/self/fd`) checking that no leaked file handles reference the original real agents home at test completion.
- **Investigation #20 & Scope:**
  - `codex-1` and `inv-astra` investigated universal arbitrary filesystem open/write sandboxing via Landlock and ptrace.
  - Per Decision #20, while the descriptor audit catches leaked handles, catching unhandled write attempts without false positives requires platform-specific ptrace supervisor complexity. The team retained the temporary environment defaults, stubbed hooks, and descriptor audit, documenting the scope without adding fragile kernel tracing.

### Item 3: `NOTIFY_CMD` Validation and Status Reporting
- **Problem:** A non-executable or relative `NOTIFY_CMD` failed late or broke runs with unbound variables, and delivery failures were invisible in status.
- **Solution:**
  - Added startup validation in `bin/agent` rejecting relative paths, non-executable files, and whitespace-only configurations (`34c7c70`, `783190c`).
  - Persisted delivery failures in `$AGENTS_HOME/notify-failure.txt`.
  - Added notification failure rendering to `agent status` until the next successful delivery.
  - Added unit tests 31, 32, and 33 in `tests/unit/agent.bats`.

## 3. Major Review Findings (M1 – M11)

### M1: Public Run, Capability Selection, and CLI Forwarding
- **Resolution:**
  - Extended `agent run` with `--need <capability>` and instance-qualified syntax (`agent@instance`).
  - Implemented `forwardCLI` in `agentbus/hub_forward.go` forwarding allowlisted CLI subcommands (`send`, `instances`, `team-create`, `team-set`, `team-done`, `team-get`) to the hub when running on a node.
  - Tested with new bats test `agent run --need routes tasks to instances with matching capabilities` in `tests/unit/instances.bats`.

### M2: Remote Wake and Command Dispatch
- **Resolution:**
  - Implemented durable node command queueing in `agentbus/hub_wake.go` (`b5ce740`) under the held bus lock (`wakeMemberLocked`).
  - Qualified member wake callsites journal owner-node wake commands instead of running remote task scripts on the hub.
  - Integrated `_node-provision` subcommand in `bin/agent` called by `agentbus/node_executor.go` when a node admits an unprovisioned remote task run (`3085c9a`).
  - Added private Unix socket support in `agentbus/node.go` (`c1011c8`) allowing the lead node to poll its local command queue without separate network credentials.

### M3: Cross-Instance Question and Answer Flow
- **Resolution:**
  - Extended `agent answer` in `bin/agent` to accept `task@instance` references.
  - Remote answers are delivered to the owning coordinator instance via `cmd-enqueue` with command kind `answer_deliver`.
  - The node executor admits the answer and applies it to `questions-$ROUND.md`.

### M4: Sensitive Work Operator Approval
- **Resolution:**
  - Implemented approval gating in `agentbus/approvals.go` (`3e6c1f2`).
  - Board items requiring sensitive capabilities (`sign:*`, `publish:*`) require local operator approval listed in `node/approved-capabilities.json`.
  - Unapproved claims fail with typed cause `NeedsApproval` (Permission class).

### M5: macOS Portability and Battery Pause
- **Resolution:**
  - Replaced direct Linux-only `flock` with `file_flock` fallback in `bin/agent`.
  - Replaced `date -Is` with portable `date_iso` and UUID generation with `generate_uuid()`.
  - Added BSD `stat -f %m` and template-required `mktemp -t`.
  - Added battery detection (`is_on_battery`) and `BATTERY_PAUSE` configuration in `agents.conf` to pause runs on battery power.
  - Updated `install.sh` for Homebrew and LaunchAgent environments.

### M6: Hang Watchdog Hub Outage Exclusion
- **Resolution:**
  - Implemented hub outage journal in `agentbus/hub_outage.go` (`dddf2cd`) writing `$AGENTS_HOME/hub-outage.json`.
  - Updated `watch_run` in `bin/agent` to subtract contiguous hub outage duration from the inactivity clock so network interruptions do not strike or kill agents.
  - Added unit tests in `agentbus/hub_outage_test.go` and `tests/unit/agent.bats`.

### M7: Reconnected Instance Member Resumption
- **Resolution:**
  - Implemented member state restoration in `agentbus/hub_maintenance.go` and `agentbus/team.go` (`e69a140`, `2f3fd05`).
  - When an instance reconnects (heartbeat or re-registration), previously unreachable members are restored to active/sleeping and woken if they have unread messages or board work.

### M8: Aggregated Status and Live Views
- **Resolution:**
  - Implemented read-only operator projection endpoint `POST /v1/view` in `agentbus/hub_view.go` (`9540e92`).
  - Implemented `agentbus snapshot` CLI subcommand emitting sanitized JSON without private quiz answers, session tokens, or local filesystem paths.
  - Integrated aggregated views into `agent status` and `live/hub_view.go`, rendering qualified `task@instance` identifiers and retaining cached snapshots with visual indicators during outages.

### M9: Detected Capabilities Discovery
- **Resolution:**
  - Implemented automatic toolchain and environment capability detection (Xcode, simulators, compilers, debug probes) in `agentbus/capabilities.go` (`85f461a`).
  - Added lead instance capability directory view without synthetic lease conflicts.

### M10: Error Contracts and Typed Enums
- **Resolution:**
  - Added generated causes in `agentbus/errors.json` and `errors_gen.go` (`77c93f8`) including `CmdInstancesError`.
  - Replaced string literals with typed constants for `Capability` and `HubAuthMode`.
  - Converted backup copy errors to concrete `*StorageError`.

### M11: Documentation and Security Reconciliation
- **Resolution:**
  - Added Multi-instance Network and Hub Security section to `README.md` covering threat models, Tailscale LocalAPI verification, TLS certificate fingerprint pinning (`HUB_CERT_SHA256`), and node execution boundaries.
  - Updated `docs/multi-instance.md` documenting `POST /v1/view` and approval workflows.
  - Updated `config/agents.conf` with `BATTERY_PAUSE` and clarified multi-instance settings.
