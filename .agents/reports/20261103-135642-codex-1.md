# Go rewrite — round 3

[PR #50](https://github.com/mateusz-szczyrzyca/team-agents/pull/50) continues R03 of
`rewrite-agent-in-go.md` from merged R02. Production still uses Bash. The Go
candidate gains application-owned execution, time and random boundaries while
keeping the existing CLI help behavior.

## Delivered

- `Command` preserves argument boundaries, including spaces and newlines, and
  defines environment, directory and stream ownership explicitly.
- `OSExecutor` starts a direct subprocess, waits synchronously, reports normal
  and signal exit codes, and preserves typed start/wait/cancellation causes.
- The default executor denies every command. `App` accepts injected boundaries;
  only the binary entry point explicitly installs `OSExecutor`.
- `Clock` supplies real time or an injected test clock. Each seeded `Random`
  owns a mutex-protected source for deterministic, concurrent noncryptographic
  draws; no shared mutable package state was introduced.
- Subprocess fixtures execute the Go test binary with isolated temporary files
  and explicit helper activation. Tests cover argv, environment replacement and
  inheritance, cwd, input/output, large output, failure causes and cancellation.
- A readiness-handshake cancellation test verifies that the direct child has
  been reaped after `Execute` returns. Callers retain ownership of streams;
  process groups and descendant cleanup remain R20 work.
- README documents the boundaries and current `520`-case parity ledger. All
  cases remain `planned`; candidate Bats activation begins in R04.

## Compatibility and review notes

- No persisted formats, public CLI commands, bus tools or Bash contracts changed.
- The Go module keeps the merged Go `1.22` minimum; no dependency was added.
- One lint suppression: `agent/process.go` uses `#nosec G204` on the intentional
  direct `exec.CommandContext` boundary. It passes explicit argv without shell
  interpolation and is available only through explicit executor injection.
- Per-instance random draws are mutex-protected. Executor calls own their local
  `exec.Cmd`, always wait after a successful start, and use the caller's context.
  Test synchronization uses context cancellation and a completion channel.

assumption. Redundant constructor-only assertions remain; App tests cover actual
