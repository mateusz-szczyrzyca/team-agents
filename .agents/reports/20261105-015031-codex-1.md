## Diagnosis and evidence

The reported gate at [`825d160`](https://github.com/mateusz-szczyrzyca/team-agents/commit/825d160d731735581493699fc1207ab9b6fb8884) registered exactly one job but failed its task-payload assertion. The original unexpected payload was unavailable, so the failure cannot be definitively attributed to a particular transaction.

Code inspection found that the fixture writes state directly while detached runner/dispatch processes can still transact. Production transactions hold `bus.lock`; an unlocked fixture update can be lost when an already-running transaction saves its earlier snapshot.

A controlled multiprocessing reproduction demonstrated that mechanism: the unlocked update ended with the original `25`-character request; the locked update retained all `65,536` replacement characters. This demonstrates the race, rather than proving the original failure's exact interleaving. Moving production terminal-status updates was rejected because scheduling may depend on them and detached dispatch can outlive the runner.
