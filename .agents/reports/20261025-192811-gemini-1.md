## Review Pass 3 Findings and Resolution

Investigation #37 (`inv-opus`) identified 1 major finding on `7a8e423`:
1. **Major N1 (`meta_set` read failure propagation)**:
   - In `meta_set`, `grep -v` was grouped with `printf` inside `{ grep -v ... || (($? == 1)); printf ...; } > "$tmp"`. When `grep` failed with exit code 2 (e.g. read / permission error), `(($? == 1))` was false, but execution continued to `printf`, giving the brace group an overall exit status of 0. This caused `mv` to overwrite `meta.env` with only the newly printed key/value line, discarding existing metadata.
   - **Resolution**: Grouped the read check and write with logical AND:
     `if ! { { grep -v "^$2=" "$f" || (($? == 1)); } && printf '%s=%q\n' "$2" "$3"; } > "$tmp"; then`
     If `grep` returns >= 2, the `printf` is skipped, the block returns non-zero, `$tmp` is removed, `meta_write_failed` is logged, and `meta_set` exits 1 while leaving the existing `meta.env` file completely intact.
   - **Test-first**: Added regression test in `tests/unit/node_checkout.bats` verifying that a child shell with fault-injected `grep` failure exits non-zero and preserves existing keys (`ID`, `AGENT`, `STATUS`). Verified failing on unpatched `bin/agent` (`RED 1697ea7`), then passing with fix (`GREEN bedeac6`).
   - **Independent verification**: `codex-1` verified `1697ea7` and `bedeac6` across 21 test cases (18 `node_checkout.bats` + 1 `meta.bats` + 2 supplemental matrix runs testing error codes 2, 3, 127 in bare and conditional contexts, byte-exact metadata preservation, and proper deletion/retention for grep 0/1 cases).
2. **Minor n2 (PR description documentation reference)**:
   - Updated PR description to drop reference to internal helper `prepare_job_task` under "Documentation".
