## Findings and resolution

Review #51 identified two remaining major findings:

1. **M4: `tests/unit/node_sync_freshness.bats` environment dependence with inherited `AGENT=1`**
   - **Cause:** When running under an environment that exports `AGENT=1` (as used by the review #51 investigator runtime), `node_read_meta` in `bin/agent` did not localize metadata variables before sourcing `meta.env`. Because the legacy fixture `meta.env` omitted `AGENT`, the inherited `AGENT=1` was captured into `Metadata.AGENT`, causing poll 1 during legacy promotion to detect an unexpected metadata change and send an upload, failing the no-sync assertion at line 103.
   - **Resolution:**
     - In `bin/agent:node_read_meta()`, initialized all 12 metadata variables (`STATUS`, `RUN`, `AGENT`, `TYPE`, `MODEL`, `NOTE`, `PAUSE_REASON`, `WAKE_AT`, `CREATED`, `FINISHED`, `JOB_ID`, `RESTARTS`) to empty strings inside the subshell prior to sourcing `meta.env`. Fallback assignments (`JOB_ID=${JOB_ID:-$jid}` and `RESTARTS=${RESTARTS:-0}`) and explicit `meta.env` values remain intact.
     - In `tests/unit/node_sync_freshness.bats`, added `unset AGENT` to `setup_test_env` to sanitize test execution.
     - Added regression test `M4: ambient runner environment variables do not leak into task metadata` verifying that ambient environment variables (`AGENT=1`, `STATUS=ambient`, `TYPE=ambient`) do not leak into task metadata during node sync.
