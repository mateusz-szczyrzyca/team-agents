## Evidence and limits

- The oracle sources configuration once per process, then secrets in the same shell. A combined
  evaluator invoked again after startup repeats executable-configuration effects.
- A short-lived retained evaluator can preserve source count, unexported config state, literal
  runtime input, delayed secrets, and separate output sinks. It need not live through the runner.
- Actual runner secrets can call the real metadata writer, mutate dynamically scoped locals, and
  replace a function invoked by the subsequent runner. Returning selected settings and environment
  cannot reproduce those continuation effects in native Go.
- Auth command-substitution and direct-provider paths have different failure/output behavior;
  investigation `#162`'s universal source-failure claim is superseded by `#163`.
- Independent coordinator replay: `python3 /var/tmp/inv163/probe.py`, exit `0`, seven cases passed.
  Replay log: `/var/tmp/r06-inv163-verification.log`; raw results:
  `/var/tmp/inv163/cases-nceetzz3/results.json`. These use isolated homes and synthetic scripts on
  Bash `5.3.9`; they establish the reported counterexamples, not exhaustive or cross-version parity.
- The auth probes retain an existing cleanup-trap `tmp: unbound variable` diagnostic. This round
  neither repairs it nor treats it as evidence of generic source-failure semantics.

The seven replay cases are summarized here so the findings do not depend on host-local artifacts:

| Case | Observed result on Bash `5.3.9` |
|---|---|
| `runner-context` | Configuration ran once; secrets saw runner/caller locals, private config state, arrays and functions, and called `meta_set` to persist `PROBE=new:3`. Configuration output kept its original streams; secrets stdout/stderr/fd 3 reached the runner log. |
| `runner-mutation` | Secrets changed `mode` and `n` and replaced `git_identity`; the later runner continuation observed `mode=fresh n=42`. |
| `auth-context` | Secrets saw auth locals and caller arguments; stdout entered the auth result and stderr stayed separate; exit `0`. The existing cleanup-trap diagnostic remained. |
| `auth-direct-failure` | `false` in secrets aborted direct provider auth with exit `1`. |
| `auth-substitution-failure` | The command-substitution auth path continued after `false`, printed `after-false`, and exited `0`; the existing cleanup diagnostic remained. |
| `runner-failure` | `false` in secrets aborted the runner with exit `1`. |
| `staged` | The retained-shell mechanism sourced config once and secrets once, retained private state, treated runtime input literally, and exited before later work. It lacked internal orchestration functions (`internal-missing`), so this was mechanism evidence rather than full parity. |
