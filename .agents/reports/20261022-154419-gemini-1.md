# Multi-Instance Coordinator Report — gemini-1

## 1. Executive Summary & Architecture Overview

Task `20261022-154419-gemini-1` implements multi-instance support for `team-agents` across Linux and macOS hosts, enabling a single agent team to span multiple machines coordinated by one hub on the lead instance.

All work strictly adhered to repository instructions (`AGENTS.md`):
- **Zero test regressions:** Existing tests were never changed, skipped, or weakened. The 3 existing test helpers (`inTeam`, `createTeam`, `teamSet`) received only comment-only `//nolint:unparam` suppressions explicitly authorized by human verdict in round 1 (`questions-1.md`).
- **Standard library only:** `agentbus` uses standard Go library modules only; no third-party dependencies were introduced.
- **Strict linting & typing:** Zero linter findings (`make lint test` clean: shellcheck, gofmt, golangci-lint, staticcheck, doccheck, errgen verification). All errors are typed per operation with typed cause enums generated via `make generate`.

## 2. Milestone Deliverables

### M0: Architecture Design & Gate
- Authored comprehensive specification `docs/multi-instance.md` resolving all architectural ambiguities:
  - Transport authentication: Tailscale LocalAPI Unix socket whois authentication and TLS token authentication with pinned SHA-256 leaf-certificate fingerprints (`HUB_CERT_SHA256`).
  - Unified endpoint `/v1/tools/{op}` handling both MCP tools and CLI operations under identical authentication envelopes.
  - Replay ledger with explicit at-most-once execution semantics; crash windows produce typed `OutcomeUnknown` (class `InvalidState`) rather than silent repeated executions.
  - Long-polling with 25-second poll chunks up to the 600-second tool timeout.
  - Closed capability vocabulary with explicit sensitivity gating (e.g. `sign:*`, `publish:*`) requiring local human approval.
  - Non-lead macOS node execution model using LaunchDaemon (`examples/launchd/com.team-agents.node.plist`) and POSIX process group supervision.
- Submitted 3 formal questions to human in round 1 (`questions-1.md`); received unanimous approval (Verdicts: a, a, a).
- Committed and pushed M0 design (`70d6e5c`) and established draft PR #4.

### M1: Hub Mode & Transport Primitives
- Incorporated and verified wire error reconstruction (`ccc4b67`, `14ace4e`):
  - Added `Unavailable` error class across all operations.
  - LocalAPI socket whois parsing with node StableID validation.
  - Owner-only Unix domain socket listener (`hub.sock`) for lead-local agents.
  - Bounded retry client with jittered exponential backoff adhering to `HUB_RETRY_SECONDS`.

### M2: Instances, Command Channel & Node Daemon
- **Instance Registration & Heartbeats (`09455d8`, codex-1, B1):**
  - Implemented `POST /v1/instances/register` and `POST /v1/instances/heartbeat` with persistent `instances.json` under exclusive bus lock.
  - Enforced monotonic report sequence numbers, session lease tokens, and lazy TTL expiry fencing.
- **Command Queue & Delivery (`24fd74b`, openrouter-haiku, B2):**
  - Implemented `POST /v1/commands/poll` (long-polling) and `POST /v1/commands/ack`.
  - Hardened ack processing with idempotent handling of identical retries and strict conflict rejection.
- **CLI Subcommands (`955a611`, gemini-1):**
  - Added `agentbus cmd-enqueue` and `agentbus instances` with dedicated unit test coverage (`TestCmdCommandEnqueueAndInstances`).
- **Outbound Node Daemon (`69e379a`, `7e402e4`, codex-1 & gemini-1, B4):**
  - Implemented `agentbus node` daemon in Go (`node.go`, `node_journal.go`, `node_transport.go`, `node_executor.go`).
  - Durable command journal (`node/state.json`, `node/daemon.lock`) preventing concurrent daemon instances.
  - Independent 60s heartbeat and 25s long-polling command dispatcher.
  - Native executor confirming execution admission via private readiness pipe (`NODE_READY_FD=3`).
  - Stdin answer injection with round and SHA-256 snapshot verification.
  - Full process group supervision and local repository policy enforcement.
- **Trusted Run Resolution (`fbcbac9`, codex-1, merged in `26a08bc`, B7):**
  - Implemented production run resolver verifying authenticated callers against live manifests and bus state (`st.Teams`, `st.Investigations`, `st.Helpers`).
  - Peer authorization callback binding requested caller instance to authenticated peer StableID (preventing tag-sharing alias borrowing).
  - Safe parsing of lead-local task metadata without executing shell expansions.
  - Optional `HubTaskSummary` metadata fields (`repo`, `branch`, `worktree`, `tier`, `role`) and `Investigation` ownership fields (`Investigator`, `Instance`) with backward compatibility test fixtures (`instances-before-run-identity.json`, `state-before-investigator-identity.json`).
  - Remote investigation records housed under fixed hub root `bus/remote-tasks/<instance>/<task>/investigations`.

### M3: Capabilities & Board Routing
- Defined closed capability vocabulary, hardware/toolchain detection (`DetectCapabilities`), and sensitive capability classification (`manifest.go`, `detect.go`).
- Implemented `find_capability` MCP tool and `board_add` `requires` capability routing with `board_claim` enforcement (`2b52c90`, openrouter-haiku, B5).
- Added `CapabilityDirectory` interface and `registryDirectory` backing.

### M4: macOS Port
- Implemented portable POSIX abstractions in `bin/agent`:
  - `file_mtime_secs`: portable mtime retrieval supporting GNU `stat -c %Y` and BSD `stat -f %m`.
  - `file_flock`: flock abstraction with python3 `fcntl.flock` fallback when `flock` utility is absent.
  - `date_iso` and `format_epoch`: portable UTC ISO 8601 formatting supporting GNU and BSD `date`.
  - `file_canonical`: portable canonical directory resolution avoiding non-portable `realpath`.
- Authored LaunchDaemon template `examples/launchd/com.team-agents.node.plist`.
- Implemented supervisor bridge subcommands (`_node-start`, `_node-wake`, `_node-stop`, `_node-mark-stopped`, `_node-answer`, `_node-manifest`).

### M5: Aggregated Views & Robustness
- Aggregated multi-instance view in terminal panel (`live/data.go`, `live/ui.go`) loading `bus/instances.json` into `Snapshot.Instances` and rendering instance status (`d2302b2`, openrouter-haiku, B6).
- Implemented `instances_status` in `bin/agent cmd_status` rendering live instances, leases, slots, and capabilities.
- Added `MemberUnreachable` to `MemberState` enum in `agentbus/types.go`.
- Periodic state backups (every 30m, keeping 10 newest in `HUB_BACKUP_DIR`) and unreachable instance reaper (`0d279ab`, openrouter-haiku, B8).
