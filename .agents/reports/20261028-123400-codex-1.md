## Compatibility and assumptions

- Existing `jobs.json`, `state.json`, messages, heartbeat formats and CLI outputs remain unchanged. No existing persisted type gained fields; no previous-format migration is needed.
- New data lives in mirror-local JSON state and node-local accepted sync state. Upgrade the lead before the nodes; older nodes simply do not upload mirrors.
- Artifacts travel as UTF-8 JSON text, with hashes computed over the delivered representation. Numbered filenames follow the closed list; hang-retry `.h` suffix files are outside that list.
- Node-wide logs piggyback on an active or retained job's sync; with no such job, they wait for one. This keeps state-report authorization intact.
- The additional incoming log-record bound is `64 KiB`.
- An identical accepted log batch is idempotent; this does not promise general log replay ordering beyond the sequential node producer.
- No new configuration variables or dependencies were introduced.
