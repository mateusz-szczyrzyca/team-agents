## B1 — instance registration and heartbeat

Implemented `POST /v1/instances/register` and `POST /v1/instances/heartbeat`, generated independent operation
error types, and added a persistent `instances.json` registry under the existing bus lock. Registration
retries for the same daemon session return the existing lease. Other live sessions are rejected. Lease
tokens use crypto/rand, replacements advance generations, expired or obsolete credentials are rejected,
and heartbeat report sequences cannot overwrite newer state. Heartbeats persist manifests and their task
summaries. Hub time and configurable `MANIFEST_TTL` determine expiry; advertised TTLs grant no authority.

Tailscale authentication carries the node StableID (or authenticated full node name for older LocalAPI
responses) separately from the requested alias. A node sharing an allowed tag cannot take over an existing
instance name. Token and private Unix socket authentication supply their own trusted peer identity. TCP
and Unix listeners share the same instance registry. Read and write failures propagate as typed storage
errors, including through the interfaces used by the command channel.

Gemini-1 supplied the shared manifest/capability types. Openrouter-haiku owns the separate command-channel
implementation; codex-1 provided the storage-aware, peer/token/generation lease-validation interface and
requested replacing the initial generation-only boolean checks before integration.

README, the approved design's endpoint details, and the configuration template document the new contracts.
No existing test was edited by this B1 change. No existing state format, CLI output, MCP schema, or exit code
was changed. A legacy fixture is loaded with an initially absent registry, then remains readable after
registration. New registry credentials and their backups must remain private.

## Remaining work and limits

B1 detects expiry in lease checks and heartbeat handling. Scheduled unreachable member transitions, board
claim release, and notifications remain M5 work. This registry does not itself grant run authority:
production Resolve must verify HubCaller against trusted registered runs, not caller-supplied identity.
The baseline HubTaskSummary lacks some role/tier/run metadata required for that resolver. Node execution,
routing, approvals, aggregated views, coherent backups and the macOS port remain with their milestones.

The inherited M1 listener has separate TCP and Unix replay-executor maps and unchecked cleanup calls;
these were reported to the coordinator for M1 integration review. B1 shares the lease registry but does
not claim those earlier replay-executor concerns are resolved. Existing instance names remain bound to
the authenticated owner after expiry; intentional owner changes require administrative reconciliation.

Manual verification for later milestones must use two Linux instances and a Mac on a tailnet: verify
cross-instance run/wake/stop, expiry/return, remote answers and complete answer broadcasts, model exhaustion
routing, signing/publishing approvals, GUI-dependent simulator/UI-test behavior and battery pause. A
macOS CI job should be proposed in the PR; no workflow was edited.
