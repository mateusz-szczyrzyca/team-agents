## B1 — instance registration and heartbeat

Implemented `POST /v1/instances/register` and `POST /v1/instances/heartbeat`, generated independent operation
error types, and added a persistent `instances.json` registry under the existing bus lock. Registration
retries for the same daemon session return the existing lease. Other live sessions are rejected. Lease
tokens use crypto/rand, replacements advance generations, expired or obsolete credentials are rejected,
and heartbeat report sequences cannot overwrite newer state. Heartbeats persist manifests and their task
summaries. Hub time and configurable `MANIFEST_TTL` determine expiry; advertised TTLs grant no authority.

Tailscale authentication carries the node StableID (or authenticated full node name for older LocalAPI
responses) separately from the requested alias. A node sharing an allowed tag cannot take over an existing
instance name. Token and private Unix socket authentication supply their own trusted peer identity. TCP
and Unix listeners share the same instance registry. Read and write failures propagate as typed storage
errors, including through the interfaces used by the command channel.

Gemini-1 supplied the shared manifest/capability types. Openrouter-haiku owns the separate command-channel
implementation; codex-1 provided the storage-aware, peer/token/generation lease-validation interface and
requested replacing the initial generation-only boolean checks before integration.

README, the approved design's endpoint details, and the configuration template document the new contracts.
No existing test was edited by this B1 change. No existing state format, CLI output, MCP schema, or exit code
was changed. A legacy fixture is loaded with an initially absent registry, then remains readable after
registration. New registry credentials and their backups must remain private.

## B4 — outbound node daemon

Implemented `agentbus node` and its checked Go runtime, journal, transport and process supervisor. The
coordinator supplied the `agent node` wrapper, current-state serializer and fixed private execution
bridges; B4 integrates them through bridge revision b9f63a5. The runtime validates configuration, pins
token-mode TLS, retains the legacy fingerprint configuration alias, and registers before polling. Its
minute heartbeat runs independently of the command loop. Session identity, manifest sequences, leases,
command acceptance, outcomes and acknowledgment cursor are persisted locally with checked sync/rename
and directory sync. A lifetime Go flock prevents a second daemon in the same home. Local node files do
not mirror the logical bus state or execute bus logic.

Command delivery validates sequence order and lease generation. Redelivery returns an already recorded
outcome; acknowledging an outcome retries across outages without dispatching again. The command-channel
author corrected the hub to accept matching acknowledgment retries and reject conflicting outcomes.
An unknown or rolled-back acknowledgment is not treated as confirmed. Remote typed endpoint errors
remain inspectable in the local operation error chain. Transient proxy/hub failures keep the daemon and
local work alive, while malformed protocols and rejected identities fail explicitly. Polling diagnostics
use warnOnce. Invalid certificate pins are configuration failures; existing Unix socket Unavailable
behavior remains unchanged.

The native executor accepts only fixed operator-installed bridge operations on local task directories,
rejects traversal/symlink escape and wrong task agents, enforces declared/sensitive capability policy,
and prevents a configured agent from working on two reserved local tasks. It supervises owned process
groups and does not trust a bare PID file to kill an unowned process. A private readiness pipe confirms
script admission before returning started/delivered; merely spawning a process is insufficient. Answers
travel on stdin and require the current question round and SHA-256 snapshot version. The coordinator
fixed answer publishing to update the questions file used by build_prompt, retain the actual round,
validate submitted answers, stop the watcher before publishing, and use a temporary file in the task
directory. No arbitrary executable, shell command or remote worktree path is accepted.

If a crash leaves acceptance without completion, the executor reports an explicit unknown outcome and
never blindly repeats process side effects. An old runner identity that this daemon cannot reconcile
requires manual inspection; it is neither killed by PID nor silently superseded. Current-daemon child
completion is tracked so normal subsequent runs can distinguish their own completed runner PID files.
This limitation is deliberate and must not be described as exactly-once launch or complete orphan
adoption after daemon restart.

B4 reuses the inherited B2 command-channel additions and integrates the coordinator's bridge/detection
updates. Files existing before this task were not changed in tests. The new node test files cover real
httptest TLS registration/heartbeat/dispatch, hub down/back registration identity, lost acknowledgment,
crash reconciliation, strict protocol and concrete remote errors, wrong certificates, local lock,
configuration, native process-group start/stop, sensitive approval, wrong task agent, repository denial,
per-agent capacity, stdin answers, readiness failure and stale-answer rejection. Actual repository-script
bridge tests use temporary homes and only early-return paths that cannot launch a real agent CLI.
Successful process supervision uses fixed synthetic script bridges.
