# TASK UNDER REVIEW

The PR implements the task below: the text the human gave this investigation, also first in the PR description
under `## Task`. Review the PR against it, not only for the quality of its code:

- Every requirement of the task is met by the PR. A requirement not met, or met only in part, is a finding.
- Where the task names an expected result (files created or changed, types, functions, tests), the PR matches it.
  An expected part missing, or a file outside it without its reason in the PR description, is a finding.
- Work the task does not ask for is a finding, unless the PR description gives its reason.
- Where the task holds several items and names the one this PR is for, review against that item.

In your result, before the findings, list the task's requirements, each marked met, partly met or not met.

Do not commit, push or open a pull request: your review is your result. The owner of the PR's branch (its merger,
or the one investigator of a team of one) fixes what you find, on this PR, and another investigator reviews the fix.
