## Executive verdict

Keep the target Rust architecture (`agent-core`, `agent-runtime`, `agent`, `agent-web`, single-owner `agent daemon` over a Unix socket, unchanged Go `agentbus` subprocess, and strict `{{name}}` template catalog), **but apply the preconditions and task-list revisions below before starting task `1.1`**.

Without these adjustments, execution fails immediately for five reasons:

1. **Missing binding rule files (§1):** None of the proposed rule files (`prompts/agent/rust-developer.md`, `prompts/worker-agent/rust-developer.md`, `prompts/investigator/rust-developer.md`, `prompts/investigator/code-review.md`) exist at [`27b39ba`](https://github.com/mateusz-szczyrzyca/team-agents/commit/27b39ba293e36633a7c07ec562d0d3c9b8626725). Task `1.1` needs the lint baseline from `rust-developer.md`, and every PR from `1.1` onward is reviewed against `code-review.md`, yet the plan schedules adding those files in `2.3`.
2. **Running Bash harness precheck bounces every Rust PR (§2):** The live harness in [`bin/agent`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/bin/agent) forbids edits to [`AGENTS.md`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/AGENTS.md) and [`.github/workflows/test.yml`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/.github/workflows/test.yml) without `agent allow`, counts `Cargo.lock` and Rust tests against `ROUND_MAX_LINES=3000`, and only recognizes Rust tests under `**/tests/**/*.rs` (bouncing any PR with only inline `#[cfg(test)]` tests as "changes code but adds no test").
3. **Unchanged `agentbus` relies on callbacks and distinct enum sets (§3):** [`agentbus/team.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/team.go) and [`agentbus/collab.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/collab.go) invoke `<wake_cmd> _wake <task>`, `<agent-cmd> _dispatch-helpers`, and `<agent-cmd> _board_done_check <task>`, and [`agentbus/types.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/types.go) rejects `tier=investigator` and any `role` other than `worker` or `investigator`.
4. **Dependency ordering defects and oversized items (§4, §8):** Three intra-/inter-feature ordering inversions (`2.2` needs `2.3`'s renderer; `7.1` needs `7.3`'s `agent gate`; `9.1` needs `7.2`'s controls and `8.1`'s PR state) and several items (`6.1` at `5.5k–7.5k` non-test lines, `8.1` at `4k–5.5k`, `4.1` at `3.5k–5k`) exceed the `4,000`-line split trigger.
5. **Cutover (`10.1`, `10.2`) and live-installation safety (§10):** Agents cannot run [`install.sh`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/install.sh) against live `~/agents` (`AGENTS.md` Never rule `3`), and `10.2` deletes `~66,000` lines across `~455` files (`11,641` lines in [`bin/agent`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/bin/agent) alone), requiring an explicit rehearsal step, a human cutover procedure, and precheck exemptions.

### 3. Unchanged `agentbus` integration boundary (`inv-astra` §§2–3, `inv-claude-sonnet` H-1, H-2)

The brief states that "`agentbus/` (Go) stays and is used as it is" and "no shared commands." In practice, `agentbus` is an active peer with its own state file (`bus/state.json`), message log (`bus/messages.jsonl`), and process callbacks:

1. **Hidden CLI callbacks invoked by `agentbus`:**
   - `<wake_cmd> _wake <task>` ([`agentbus/team.go#L96`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/team.go#L96)): spawned detached when a `sleeping` team member receives a message (after `agentbus` transitions the member to `waking`).
   - `<agent-cmd> _dispatch-helpers` ([`agentbus/collab.go#L934`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/collab.go#L934)): spawned detached (`setsid`) when an agent calls `delegate`.
   - `<agent-cmd> _board_done_check <task>` ([`agentbus/collab.go#L102-L130`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/collab.go#L102-L130), [`#L617`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/collab.go#L617)): run synchronously inside `board_done` (`0` = allow, `3` = refuse with stdout reason shown to the agent, any other exit code or `60 s` timeout = log warning and allow completion).
   - **Resolution:** Carve out an explicit compatibility exception in `6.1` for `_wake`, `_dispatch-helpers`, and `_board_done_check` on the Rust `agent` binary as thin socket clients of `agent daemon`, plus periodic/startup bus reconciliation in the daemon in case a callback ran while the daemon was restarting.
2. **Type and flag translation at the `agentbus` boundary:**
   - [`agentbus/types.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/types.go) accepts `Tier` values `normal` and `worker` only (not `investigator`) and `Role` values `worker` and `investigator` only (not `solo`, `coordinator`, `member`, `worker`, `reviewer`). `agent-runtime` must translate harness `Tier`/`Role` to bus `Tier`/`Role`.
   - `agentbus serve` requires the full flag vector (cf. `bus_args_json` in [`bin/agent#L4386`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/bin/agent#L4386)): `--agent`, `--task`, `--task-dir`, `--repo`, `--branch`, `--worktree`, `--peers`, `--role`, `--queue-max`, `--inv-slots` (set to `0` so out-of-scope `request_investigation` advertised by [`agentbus/main.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/main.go) refuses cleanly instead of queuing invisible work), `--tasks-dir`, `--team`, `--tier`, `--agent-cmd`, and `--home`.
3. **Subcommand semantics and undocumented CLI commands:**
   - `team-create` ([`agentbus/team.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/team.go)) overwrites an existing team entry; recovery must query `team-get` before calling `team-create`.
   - `helper-next` claims a queued delegation by mutating state, and `helper-set` updates status without notifying the requester ([`agentbus/collab.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/collab.go)); the daemon must explicitly `send` the worker's result message and reconcile claimed helpers on restart.
   - `4.2` mentions "board release", whereas the CLI dispatcher in [`agentbus/main.go`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/main.go) exposes `board-release-agent` (all items for an agent). Also, `board-add`, `board-claim`, `claim-lead`, and `delegate` exist in [`agentbus/main.go#L1454`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/agentbus/main.go#L1454) but are omitted from `agentbus`'s usage text; `4.2` must pin them with integration tests against the compiled `agentbus` binary.
4. **Dual-store authority (`docs/state.md` in `2.2`):**
   - `agentbus` is authoritative for agent-mutated MCP state: messages, read cursors, board items (`B1…`) created by coordinators for workers, delegation queue, notebooks, and checkpoints.
   - `agent daemon` is authoritative for tasks, runs, task-list items (`2.3` assigned by the daemon to team members), PRs, reviews, gates, and member scheduling (pushing availability to the bus via `team-set`).

### 5. GitHub API, revision pinning, review scheduling, and `--no-merge` (`inv-astra` §§5–7, 11; `inv-claude-sonnet` H-3, M-1, M-7)

- **Draft-to-ready requires GraphQL or non-draft creation:** GitHub's REST `PATCH /repos/{owner}/{repo}/pulls/{pull_number}` cannot clear `draft`; only the GraphQL mutation `markPullRequestReadyForReview` does. Either open the PR directly as ready once the gate is green (simplest) or issue the single GraphQL POST via `reqwest`.
- **Self-reviews under a single GitHub account:** Because all agents share one GitHub token, GitHub rejects `APPROVE` and `REQUEST_CHANGES` review events on one's own PR. Reviews must be posted as `COMMENT` reviews (with agent/model attribution bylines, cf. [`prompts/review.md`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/prompts/review.md)), while the daemon parses the structured verdict from the reviewer's report.
- **Exact-revision pinning across gate, reviews, and merge:**
  - Record `(item_id, run_id, branch, head_sha, tree_clean)` on every gate result. A dirty/merge-in-progress gate is permitted for coordinator development (`7.3`), but only a `tree_clean == true` pass on the exact `head_sha` authorizes PR creation or review launch (`8.1`).
  - Bind both reviewer runs to `head_sha`; any new push invalidates prior gate and review approvals, and late verdicts from superseded/canceled reviewer runs are ignored.
  - Pass `sha: head_sha` and `merge_method: "merge"` to `PUT /repos/{owner}/{repo}/pulls/{pull_number}/merge` (matching `--match-head-commit` in [`bin/agent#L2399`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/bin/agent#L2399)).
  - Handle merge conflicts (`405`/`409` when a parallel feature merges) by routing back to the coordinator to merge the updated base and re-gate, and run a post-merge gate on `origin/<base>` (matching [`bin/agent#L2410`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/bin/agent#L2410)).
- **Reviewer-pair selection (`3.1` + `8.1`):**
  - Move reviewer-pair selection into pure decisions (`3.1`): reserve two free outside investigators atomically so two competing teams never claim one investigator each and deadlock.
  - Define "free" = no active model run and not paused by quota/rate limit (an investigator coordinator waiting for external reviews has no active run and may review another team's PR, never its own). Ensure solo investigator tasks also require two outside investigators.
- **`--no-merge` branch stacking:**
  - Under `--no-merge`, item `N.2` starts when `N.1` is approved by both reviews (before the human merges `N.1`). Branching `N.2` from `main` would miss `N.1`'s code; `N.2` must branch from `N.1`'s approved head (setting its PR base to `N.1`'s branch until the human merges `N.1`), while cross-feature `Depends on:` waits for actual merges. Also treat `[x]` task-list items as completed prerequisites without fabricating PR/review state.

### 6. Daemon crash recovery, process containment, socket auth, and gate lock scope (`inv-astra` §§8–9, 12; `inv-claude-sonnet` M-2, M-3)

- **Durable pending-effect outbox:** Atomic file rename (`SEC-5`) protects state reads, not multi-step external mutations (spawning a run, creating a PR, merging, posting a review, claiming a helper). Persist pending operation intents before external calls and reconcile on restart (e.g., query open PRs by `head` branch before creating; treat "already merged" as success).
- **Daemon restart vs running children (`KillMode`):** Under systemd's default `KillMode=control-group`, `systemctl --user restart` kills all running model CLIs, forcing session resume on every restart. Document the choice in `6.1` (`KillMode=control-group` with session resume vs `KillMode=process` with PID/process-group re-adoption). Recovery must only resume runs interrupted mid-flight — never tasks that were manually stopped, paused, or waiting on questions.
- **Per-run capability token on the daemon socket (`SEC-3`):** Mode `0600` authenticates the OS UID, and model CLIs run under that same UID with `--dangerously-skip-permissions` / `--dangerously-bypass-approvals-and-sandbox` ([`bin/agent#L4568`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/bin/agent#L4568)). Pass a per-run token in the child environment so the daemon socket restricts agent processes to `gate` and the three `agentbus` callbacks, forbidding `answer`, `stop`, `resume`, and `say`. Never pass the GitHub token in model/editor/git environments.
- **Gate lock scope and recursion (`7.1`):** [`tools/test-lock.sh`](https://github.com/mateusz-szczyrzyca/team-agents/blob/27b39ba293e36633a7c07ec562d0d3c9b8626725/tools/test-lock.sh) holds `/tmp/.make.command.lck` across the host and routes `make gate` through `agent gate` when `AGENT_RUN_TASK` is set. When `agent daemon` runs the repository's gate command (`make gate`), it must strip/mark the environment so `make gate` does not recursively re-enter `agent gate` and deadlock the FIFO queue, while coordinating with `/tmp/.make.command.lck` during Bash/Rust coexistence.
- **Serena MCP & process bounds:** Feature `5` includes Serena MCP configuration, so `agents.toml` (`2.1`) and the subprocess policy must include optional Serena command/arguments alongside `agentbus serve`. Name explicit byte/line limits for stdout/stderr records, error tails, socket frames, and SSE queues (`CON-5`).
